HOW TO CODE A FIGHTER

SFFG community character format · v3 — the Freedom Update

Everything a fighter is — stats, moves, frame data, hitboxes, sprites, passives, projectiles — lives in one JSON object plus a folder of sprite sheets. There is no scripting: a mod is pure data, which is exactly why community fighters can't break the game, steal anything or desync online matches. If the no-code Fighter Creator can express your idea, use it — it produces this same format. This page is for people who want to hand-write or generate the JSON.

Open the Fighter Creator Back to SFFG
The Freedom Update (v3): balance limits are gone. Every number is only bounded by wide security ranges that protect the deterministic engine and the renderer — not fairness. A 999999-damage jab is legal. The tier system rates it with the same formula as everyone else and slaps omnipotent regular guy on the card, so nobody walks in blind.

1 · The shape of a fighter

{
  "name": "Uncle Ekber",            // 1-32 chars
  "tagline": "He warned you.",      // up to 90 chars
  "color": "#ff8c00",               // main color (puppet body, projectiles, UI)
  "color2": "#ffd9a0",              // accent
  "skin": "#d8a878",                // puppet skin tone

  "hp": 1000,                       // 1-999999
  "walk": 68, "back": 52,           // px per frame ×16, 0-2000
  "jumpVX": 56, "jumpVY": -252,     // jump drift / power (negative = up, to -2000)
  "grav": 14,                       // 1-200 (1 = moon, 200 = brick)
  "w": 56, "h": 150, "crouchH": 105,  // body box in game pixels
  "projMax": 2,                     // optional: live projectiles at once, 1-6

  "passive": {                      // all optional, these are the neutral values
    "regen": 0,                     // hp per second
    "defense": 100,                 // % damage taken (0-1000; 50 = tank, 300 = glass)
    "meterMult": 100,               // % meter gain (0-10000)
    "lifesteal": 0                  // % of damage dealt healed back, 0-100
  },

  "sprite": { ... },                // optional — omit for the vector puppet
  "moves": { ... }                  // required — see below
}

2 · Moves

Nine standard slots plus unlimited custom ones. light, heavy, special, air, throw and super are required; clight / cheavy (crouching) and burst are optional. Any other lowercase key (e.g. "slash2") becomes a custom move, reachable only through chains — up to 32 moves total. Each move:

"special": {
  "name": "Get Off My Lawn",
  "dmg": 120,                      // 0-999999. yes, really
  "startup": 12, "active": 4, "recovery": 20,   // frames (60/s), each up to 600
  "hitstun": 22, "blockstun": 12, "hitstop": 9, // hitstop caps at 60 (a 1s freeze is enough drama)
  "kbx": 130,                      // knockback; NEGATIVE pulls them toward you
  "box": {"x": 30, "y": -130, "w": 90, "h": 40}, // hitbox from your feet, facing right
  "hits": "low",                   // optional: "low" | "high" (air moves default to high)
  "launch": 1, "kby": -230,        // optional: knocks airborne
  "step": 60,                      // optional: movement during startup+active (negative = retreat)
  "armor": 1,                      // optional: absorbs one hit during startup/active
  "armorBreak": 1,                 // optional: ignores enemy armor
  "inv": 1,                        // v3: invulnerable startup on ANY move
  "chip": 25,                      // v3: % of dmg that leaks through block (0-100, chip can KO)
  "crouch": 1,                     // v3: use the crouching hurtbox during this move
  "nonAttack": 1,                  // v3: pure animation, no hitbox (taunts, stances)
  "nextA": "slash2",               // v3: chain — pressing Light near the end flows into "slash2"
  "nextB": "heavy",                // v3: same for Heavy…
  "nextC": "special",              // v3: …and Special. Chains work whiffed or on hit.
  "projectile": {                  // optional: fires when the move becomes active
    "speed": 90,                   // fine units per frame; NEGATIVE fires backward
    "life": 50,                    // 1-3600 frames
    "w": 24, "h": 24,
    "vy": -60, "grav": 8,          // v3: launch angle + gravity = arcing shots
    "bounce": 1,                   // v3: bounces off the floor instead of dying
    "pierce": 2                    // v3: survives this many extra hits (0-8)
  },
  "anim": "special",               // optional: which sprite sheet plays
  "impact": 6                      // optional: which drawing is the hit (default: 2nd-to-last)
}

Burst: give your fighter a burst move and it works exactly like Parasoul's — all three attack buttons during hitstun, costs half the meter, great with inv and a big box around the body. Chains: the classic magic series (light → medium → heavy) is light.nextA = "light2", light2.nextA = "light3" — the chained press has to land in the last active frame or later, exactly like Parasoul's.

The rock-paper-scissors rules are engine-wide and free: lows must be blocked crouching, air attacks standing, throws beat block but whiff on airborne/stunned targets, 4-hit juggle cap, combo damage scaling. Live projectiles cap at your projMax (up to 6).

3 · Sprites

Optional — a fighter without sprites plays with the built-in vector puppet, which is a totally respectable look in this game. If you do use sprites:

  • Each animation is one horizontal strip PNG: same-size cells, frames left to right.
  • cw/ch = cell size · cx = body center x inside the cell · fy = feet line y inside the cell.
  • Attacks: author strips as windup…, impact, follow-through — the engine plays windup drawings across the startup, holds the impact drawing during active frames, and spreads the rest across recovery. Few drawings + fast gameplay is fine; chunky is a feature.
RequiredOptional
idle, run, jump, fall, attack1, attack2, hit, death walkback, dash, backdash, block, getup, crouch (stand→kneel, held), clight, cheavy, airatk, special, super, attack3, attack4, burst — or since v3 any lowercase custom key a move's anim points at (up to 40 animations)
"sprite": {
  "scale": 0.58,        // game px per cell px
  "smooth": 1,          // 1 = HD art, 0 = crisp pixel art
  "idleTop": 8,         // top of the head in the idle cell (portrait crop)
  "anims": {
    "idle": {"f":"idle.png","n":8,"cw":164,"ch":268,"cx":82,"fy":263},
    "run":  {"f":"run.png","n":7,"cw":141,"ch":268,"cx":70,"fy":263}
    // ... one entry per sheet; file names: lowercase letters/numbers + .png
  }
}
The Creator builds all of this for you from loose frame images — including background removal and feet alignment. Hand-author strips only if you enjoy pain or scripts.

4 · Controls & keybinds

SFFG's input grammar is fixed for every fighter — 4 directions + light/heavy/special, with throws on light+heavy and supers on heavy+special. That's deliberate: online play sends only these buttons, so any two fighters are automatically netplay-compatible. Your creativity lives in what each slot does: an 8-frame invincible reversal, a slow armored bulldozer, a pull-in whip, a projectile zoner — all expressible in data. Players can remap their own buttons in Controls on the game menu (bindings are per-player, not per-character, so nobody has to learn your layout).

5 · Validation rules (the bouncer)

Before a fighter loads — in the Creator, at upload, and again in every player's game — it runs through sffg-mods.js. Since v3 the bouncer checks security, not balance:

  • Whitelists every field and drops anything unknown (there is no way to smuggle code — a mod is data, never a script).
  • Clamps every number into wide security ranges that protect the deterministic engine (integer safety, no infinite freezes, no un-renderable sprites). Nothing is clamped for being "too strong".
  • Strips matchup fields (weakTo) — counters are an official-roster mechanic.
  • Requires the six core moves and, if sprites are used, the eight core animations.
  • Caps totals: 32 moves, 40 animations, 150 KB of JSON, sheets ≤16384px wide — browser limits, not creative ones.
  • Drops chain references to moves that don't exist.

The tier system then rates your fighter with the same formula as the official roster — damage per committed frame, reach, mobility, hp, gimmicks, passives, and the new v3 toys (chip, pierce, lifesteal, invincible normals all score). Your one-touch-kill monster is legal now; it will simply wear the omnipotent regular guy badge, and everyone gets to see it coming.

6 · Publish it

Publishing needs a Chill Zone account (browsing and playing community fighters doesn't). Two ways:

  1. Creator: create.html → build → Publish to SFFG. Done.
  2. Hand-written JSON: Creator → Import JSON → re-attach your sprite frames → Publish. The importer runs the validator and shows you every complaint.

Your fighter appears in the community section of the character select for everyone, instantly playable in local and online matches (online transfers it by id + content hash so both players are guaranteed the same data). You can edit or delete it any time from My fighters in the Creator.

Own your art. Ripped, traced or repainted sprites from commercial games get removed and repeat offenders lose upload rights. CC0/original art only — the same rule the official roster follows. If you're unsure whether a pack is legit, ask in the chat first.
